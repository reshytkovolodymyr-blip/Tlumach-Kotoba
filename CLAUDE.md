# CLAUDE.md

Контекст для Claude Code при роботі над **Tlumach Kotoba** — тренажером
англійської та японської мов для україномовних, побудованим навколо
принципу "AI створює діалог → застосунок перетворює його на аудіо-урок".

Прочитай цей файл перед першою правкою. Він описує архітектурні
рішення, які НЕ випадкові — і чому їх не варто "спрощувати" назад.


## Запуск і перевірка

```
py tlumach_kotoba.py                          # запустити застосунок
py -m py_compile tlumach_kotoba.py app/*.py   # перевірити синтаксис
py tests/test_current_session.py              # критичний тест CURRENT SESSION
py tests/test_shadowing_and_phrases.py        # тест Shadowing (3 проходи) + Phrase Trainer
py tests/test_japanese_reading.py             # тест романізації (сам себе пропускає без pykakasi)
py tests/test_voice_selection.py              # тест автоматичного підбору моделі голосу
```

Після БУДЬ-ЯКОЇ зміни в `app/session.py`, `app/exercises.py`,
`app/languages.py` чи `app/parser.py` — обов'язково прогнати всі
чотири тестові файли. Вони не використовують pytest, просто
`python file.py`, кожен завершується з ненульовим кодом виходу через
`assert`, якщо щось не так.

Немає дисплея/GUI-тестування в CI — `PySide6` тут НІКОЛИ не був
встановлений і не запускався (пробував `pip install PySide6` —
недоступний навіть з дозволеною мережею PyPI, ймовірно через розмір
пакета). `py_compile` і AST-парсинг спрацьовують і БЕЗ встановленого
PySide6 (компіляція не виконує імпорти) — тому синтаксис і
відсутність друкарських помилок перевірені, а ось реальна поведінка
Qt-віджетів (чи правильні назви методів/enum, чи працюють сигнали) —
ні, жодного разу. Про це варто прямо попереджати користувача після
кожної зміни GUI.


## Архітектурні принципи (не порушувати без явного запиту)

1. **CURRENT SESSION.** У програмі завжди рівно один активний урок.
   `SessionManager.create_from_text()` і `.set_current()` — єдині
   способи його змінити, і обидва ПОВНІСТЮ замінюють попередній
   об'єкт, ніколи не дописують. Критичний тест
   (`test_current_session.py`) перевіряє це на реальному сценарії
   Airport→Hotel→History→Airport→Job Interview.

2. **Голос спікера: стать вручну, конкретна модель — автоматично.**
   `speaker_voices[speaker]` зберігає ЛИШЕ `"male"`/`"female"`,
   обране вручну через комбобокс у GUI (без дефолтного значення, без
   вгадування статі за іменем). Конкретну модель голосу підбирає САМА
   програма, випадково, у `ExerciseGenerator._speaker_voice_map()`
   (`languages.pick_voice`) — користувач цього вибору не бачить.
   Результат кешується в `session.resolved_voices` (ефемерне поле,
   НЕ зберігається в JSON/SQLite) — щоб той самий спікер звучав
   ОДНАКОВО в усіх файлах одного екземпляра сесії (Full Dialogue і
   Shadowing того самого уроку не повинні розходитись голосом), але
   новий розбір діалогу чи повторне завантаження з History дають
   новий випадковий вибір. Голос перекладу (рідна мова, Остап/
   Поліна) — та сама логіка через `pick_native_voice()` і
   `session.resolved_native_voice`.

   ⚠️ Це вже ОДИН РАЗ відкочувалось: локальна сесія Claude Code
   була змінила архітектуру на повний РУЧНИЙ вибір конкретної моделі
   голосу (комбобокс "Guy — чоловічий", "Davis — чоловічий"...) —
   якщо десь у git-історії зустрінеться `voice_options()` чи
   `native_voice_options()` в `languages.py`, це стара, свідомо
   відкинута гілка розвитку. НЕ повертати ручний вибір конкретної
   моделі — узгоджений з користувачем варіант саме автоматичний.

   ⚠️ ДРУГИЙ інцидент (уже трапився, теж не повторювати): пул
   `voices` у `languages.py` НАРАЗІ звужений до РІВНО ОДНОГО голосу
   на стать (`en-US-GuyNeural`/`en-US-JennyNeural`,
   `ja-JP-KeitaNeural`/`ja-JP-NanamiNeural`). Раніше пул був
   розширений (Davis, Jason, Tony, Daichi, Aoi...), перевірений через
   ОФІЦІЙНУ Azure-документацію — але edge-tts НЕОФІЦІЙНА бібліотека
   (звертається до вужчого сервісу "Читати вголос" у Microsoft Edge,
   не до платного Azure API), і належність голосу до каталогу Azure
   НЕ означає його доступність через edge-tts. Розширений пул
   постійно давав користувачу помилку `"Не вдалося підключитися до
   TTS. Перевірте Internet."` — хоча інтернет був ні до чого, просто
   частина voice_id не існувала в edge-tts. ЄДИНИЙ надійний спосіб
   додати голос у пул — реальний вивід команди
   `edge-tts --list-voices` на машині з Internet, ніколи —
   документація Azure чи сторонні списки голосів.

3. **Переклад ніколи не вигадується.** `Phrase.meaning_uk`
   заповнюється лише якщо в тексті AI реально є кирилиця після
   роздільника (` - `, ` — `, дужки). Немає перекладу — програма
   каже "Translation unavailable", а не підставляє щось своє.

4. **Ключові фрази — виключно зі списку AI.** Був колись
   regex-fallback для англійської (пошук "Could you", "I'd like
   to"…) — свідомо видалений як вгадування. НЕ повертати його.
   `parser.py` розпізнає рядок фрази з номером і без (AI часто
   забуває нумерувати) — обидва варіанти покриті тестом
   `test_phrase_list_without_numbers_still_recognized`.

5. **`practice` (пари Recall) ніколи не зберігається** — завжди
   обчислюється на льоту з `dialogue` (`LessonSession.practice_pairs`).

6. **`raw_text` зберігає ПОВНИЙ оригінальний текст від AI** окремо
   від розібраних `dialogue`/`phrases`. При завантаженні уроку з
   History чи Import JSON — `_set_form_from_session()` в `gui.py`
   відновлює саме цей текст у полі редагування, а не перегенеровує
   його з розібраних даних.

7. **GUI не містить бізнес-логіки.** Розбір тексту, TTS, FFmpeg,
   SQLite — усе в `app/`, `gui.py` тільки викликає й показує.

8. **`.bat`-файли — ЛИШЕ ASCII, без кирилиці.** Перевірено на
   практиці: `chcp 65001` + кирилиця в batch-файлі призводить до
   того, що `cmd.exe` "з'їдає" символи на межах рядків (`echo` →
   `cho`, `if %errorlevel%` → голий `errorlevel`). Усі три `.bat`
   зараз чисто англійською з CRLF — не додавати туди кирилицю знову.

9. **Shadowing = 3 проходи**, не один: повільно (пауза ×2) →
   природний темп → без паузи ("наздоганяючий"). Кожен прохід має
   словесний маркер українською на початку (`NATIVE_LANGUAGE_VOICE`).

10. **Phrase Trainer = 2 блоки**: форма-і-значення (фраза → повільно
    → переклад → приклад) для ВСІХ фраз, потім активне пригадування
    (переклад → пауза → фраза) лише для фраз, що МАЮТЬ переклад.

11. **GUI показує тільки 3 режими** (Full Dialogue, Shadowing,
    Ключові фрази) через `Radiobutton`, один файл за раз — навмисно
    БЕЗ комбінування в одному кліку (це було і відкотили назад).
    Recall/Reverse Recall лишаються повністю робочими в
    `exercises.py`, просто не підключені в `gui.py`.

12. **Залежність — `pygame-ce`, НЕ `pygame`.** Класичний pygame не
    має wheels для нових версій Python на Windows (падає на
    `setuptools._distutils.msvccompiler`, бо distutils прибрано з
    Python 3.12+). Import у коді лишається `import pygame` — це
    працює однаково для обох пакетів, міняти імпорт не треба.

13. **Плеєр ніколи не автовідтворює після генерації MP3.**
    `_load_into_player(path, auto_play=False)` у `gui.py` після
    успішного `_on_create_audio` — файл лише завантажується, Play
    користувач тисне сам. `auto_play=True` лишається тільки для
    ручного "🎵 Відкрити файл" (там це очікувана поведінка).

14. **Промпт для AI не вимагає прикладу речення й не вимагає
    нумерації.** `prompt_builder.py` просить рівно
    `фраза - переклад` в один рядок, без `| приклад: ...`. Парсер
    (`parser.py`) і далі ВМІЄ розпізнати приклад через `|`, якщо
    AI сам його додасть (backward-compat), просто промпт більше
    цього не вимагає — спрощення за прямим запитом користувача.

15. **Історію можна видаляти:** по одному запису (права кнопка миші
    → "Видалити") і всю одразу (кнопка "🗑 Очистити всю історію").
    Обидва шляхи — `database.py`: `delete_session()`/`clear_history()`
    — і жоден не чіпає таблицю `events` (лічильники статистики
    лишаються правдивою історією навіть після видалення уроків).

16. **Поле "Діалог від AI"** (`QPlainTextEdit`) має власну вбудовану
    прокрутку — на відміну від старої Tkinter-версії, тут не потрібно
    вручну прив'язувати `Scrollbar`, Qt-віджети скроляться самі.

17. **Перед перезаписом MP3, завантаженого в плеєр — обов'язково
    `player.unload()`.** На Windows pygame/SDL_mixer тримає файл
    відкритим (дескриптор) навіть після `stop()`, поки не викликати
    саме `unload()`. Якщо FFmpeg спробує перезаписати такий файл без
    попереднього `unload()` — падає `Permission denied` (реальний
    інцидент, трапився на практиці). `_on_create_audio()` у `gui.py`
    робить це автоматично, ЛИШЕ коли `self.player.loaded_path`
    збігається з файлом, який зараз перезаписується — не викликати
    `unload()` безумовно на кожну генерацію, це перерве відтворення
    геть іншого файлу, який користувач міг слухати паралельно.

18. **Конфлікт імені файлу — завжди запит користувачу, ніколи тихий
    перезапис.** `AudioAssembler.target_path()` обчислює ім'я БЕЗ
    побічних ефектів (не створює нічого) — GUI перевіряє
    `.exists()` ДО запуску синтезу (не після) і питає через
    `messagebox.askyesnocancel`: перезаписати (`final_path` =
    той самий шлях) / зберегти новим (`final_path` =
    `next_available_path()`, суфікс `_2`, `_3`...) / скасувати
    (return, синтез не запускається взагалі). `build()` приймає
    необов'язковий `final_path` саме для цього — якщо не передати,
    поведінка як і раніше (обчислює сама).

19. **`.github/workflows/build-windows.yml` включати в КОЖНЕ
    пакування проєкту, завжди, без нагадування.** Це не опційний
    файл — користувач явно попросив, щоб він був у ВСІХ наступних
    генераціях без винятку. Причина: я (Claude) працюю в Linux-
    середовищі й фізично не можу зібрати Windows `.exe` сам
    (PyInstaller не має кросс-компіляції) — цей workflow дає
    користувачу безкоштовну хмарну збірку на справжній Windows-
    машині GitHub замість локальної збірки через `BUILD_EXE.bat`.
    Прапорці PyInstaller у ньому мають лишатись ІДЕНТИЧНИМИ до
    `BUILD_EXE.bat` — якщо один змінюється (нова залежність,
    новий `--collect-all`), оновити обидва одночасно.


## Структура

```
tlumach_kotoba.py       — точка входу
app/
    parser.py            — DialogueParser: "Ім'я: репліка" + фрази (мовонезалежний, без romaji/TTS-логіки)
    languages.py          — TARGET_LANGUAGES + pick_voice()/pick_native_voice() (автопідбір моделі)
    prompt_builder.py      — генерує текст промпту для зовнішнього AI
    wizard.py               — стартовий Toplevel-майстер (мова/рівень/тема → промпт)
    japanese_reading.py      — pykakasi wrapper, романізація
    session.py                — LessonSession + SessionManager (CURRENT SESSION, resolved_voices)
    tts.py                     — TTSEngine/EdgeTTSEngine/TTSManager
    audio.py                    — AudioAssembler: сегменти → один MP3 через FFmpeg
    exercises.py                 — ExerciseGenerator: 5 методів-режимів
    database.py                   — SQLite: sessions + events, delete_session/clear_history
    player.py                      — AudioPlayer (pygame.mixer.music, load()/play() окремо)
    content.py                       — двомовний (UK/EN) текст «Методологія»/«Про програму»
    settings.py                       — персистентна мова інтерфейсу (settings.json)
    gui.py                             — PySide6-інтерфейс, QStackedWidget для вкладок
examples/               — приклади для кнопки "Приклад уроку" (EN + JP + FR + ES)
assets/icon.ico          — іконка (НЕ перегенеровувати, надана користувачем)
tests/                   — чотири файли, запускаються напряму python-ом
```

## Відомі больові точки (уважно при зміні GUI)

- **PySide6 тут ніколи не був встановлений і не запускався** (навіть
  `pip install PySide6` не спрацював у середовищі розробки — пакет
  недоступний). Кожна зміна в `app/gui.py`/`app/wizard.py`
  перевірена лише `py_compile`/AST (синтаксис), НІКОЛИ наживо. Помилки
  в назвах методів/enum Qt чи логіці сигналів можливі й не будуть
  виявлені, поки хтось реально не запустить застосунок на Windows.
- Довгі операції (TTS + FFmpeg) виконуються в `AudioWorker(QThread)`
  із сигналами (`status_changed`/`finished_ok`/`failed`) — НІКОЛИ не
  чіпати віджети напряму з `run()` цього класу, Qt не гарантує
  потокобезпеку для прямого доступу до UI з фонового потоку.
- Кнопки статі спікера (`QComboBox` у "Голоси спікерів") мають
  першим порожній рядок ("") — це навмисний замінник "не обрано",
  аналог відсутності дефолтного значення в старій Tkinter-версії.
- `text_shortcuts.py` видалений — Qt-віджети (`QLineEdit`,
  `QTextEdit`) мають надійні вбудовані Ctrl+C/V/X/A, окремий модуль
  для цього більше не потрібен.
- Файли шрифтів (Fraunces, IBM Plex Sans з дизайн-макета) НЕ
  включені в `assets/fonts/` — Google Fonts недоступний з мережі
  середовища розробки. `load_app_fonts()` у `gui.py` тихо переходить
  на системний Segoe UI, якщо файлів немає. Якщо колись покласти
  реальні `.ttf` в `assets/fonts/` — підхопляться автоматично, без
  зміни коду.


## Інтерфейс після редизайну (кроки 1→2→3)

- Вкладка «Новий урок» — три кроки: 1 Створи урок → 2 Налаштуй
  голоси → 3 Практикуйся. Кроки — це три віджети в одній колонці,
  видимий лише поточний (НЕ QStackedWidget: той бере висоту
  найбільшої сторінки і лишає порожнечу на коротких кроках). Крок 2
  доступний лише з розібраним уроком, крок 3 — лише коли всім
  спікерам обрано стать (`_step_allowed`).
- Єдина точка оновлення UI після зміни CURRENT SESSION —
  `_on_session_changed()` (новий розбір, історія, імпорт, видалення).
- Статуси й попередження — inline-плашки (`_set_note`), спливаючі
  вікна лише для підтверджень і помилок.
- Стать спікера — дві кнопки «Жіночий/Чоловічий» (без дефолту), виклик
  тільки через `session.set_speaker_gender()`.
- Масштаб: `build_stylesheet(scale, ...)` генерує QSS з коефіцієнтом;
  відступи макетів реєструються через `_lay()`, щоб масштабуватись.
  Динамічні віджети (картки спікерів) НЕ реєструються в `_lay()` —
  вони перебудовуються в `_apply_zoom()`; реєстрація знищених віджетів
  призвела б до звернення до видалених C++-об'єктів.
- Вікно відкривається 1120×720 (обмежено екраном), розмір/позиція і
  масштаб зберігаються в settings.json (`window_geometry`, `zoom`).
- Прогрес MP3 береться з рядків статусу audio.py («Озвучення N: …»,
  «Об'єднання …») — якщо змінити ці рядки в audio.py, оновити
  `_on_worker_status()` у gui.py.
- Нові написи кроків — у кінці content.py (`_UI_STEPS`, `_MSG_STEPS`,
  `COUNT_FORMS`); там же кілька старих ключів перевизначені на
  коротші, без емодзі.


## Сайт і публікація (site/, DEPLOY_GUIDE.md)

- `site/` — статичний сайт для Cloudflare Pages (Build output directory =
  `site`, без команди збірки): `index.html`, `methodology.html` (зібрано з
  окремого документа методології), `404.html`, іконки. Самодостатні HTML,
  без JS-фреймворків, світла й темна теми через CSS-змінні.
- Посилання на завантаження — `https://github.com/YOUR_GITHUB_NAME/tlumach-kotoba/releases/latest/download/TlumachKotoba.exe`.
  Заглушку `YOUR_GITHUB_NAME` користувач замінює сам (DEPLOY_GUIDE.md,
  крок 2) — НЕ підставляти вигадане ім'я.
- `build-windows.yml` тепер також запускається на `release: published` і
  прикріплює `.exe` до релізу (softprops/action-gh-release). Зміни лише в
  `site/**` і `**/*.md` збірку не запускають (paths-ignore). Прапорці
  PyInstaller як і раніше дзеркальні до BUILD_EXE.bat.
- `DEPLOY_GUIDE.md` — покрокова інструкція користувачу (GitHub, реліз,
  Cloudflare). Оновлювати разом із будь-якою зміною workflow чи site/.
