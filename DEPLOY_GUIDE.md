# Як опублікувати Tlumach Kotoba: GitHub + Cloudflare

Ця інструкція проводить від розпакованого архіву до двох результатів:

1. **Репозиторій на GitHub**, який сам збирає готову програму
   `TlumachKotoba.exe` (Python на вашому комп'ютері не потрібен) і
   публікує її в розділі **Releases**.
2. **Сайт на Cloudflare Pages** (безкоштовно), кнопка «Завантажити» якого
   веде прямо на `.exe` з останнього релізу.

Усе живе в **одному** репозиторії:

```
tlumach-kotoba/                ← корінь репозиторію
├── .github/workflows/build-windows.yml   ← інструкція збірки .exe для GitHub
├── app/                        ← код програми
├── assets/  examples/  tests/
├── site/                       ← сайт (саме цю теку показує Cloudflare)
│   ├── index.html
│   ├── methodology.html
│   ├── 404.html
│   ├── favicon.png
│   └── apple-touch-icon.png
├── tlumach_kotoba.py
├── requirements.txt
├── DEPLOY_GUIDE.md             ← цей файл
└── …
```

Орієнтовний час: 30–40 хвилин уперше. Знадобляться безкоштовні акаунти
на [github.com](https://github.com) і [cloudflare.com](https://dash.cloudflare.com/sign-up).

---

## Крок 1. Розпакуйте архів

1. Розпакуйте `tlumach_kotoba.zip`. Усередині буде тека `lps`.
2. **Важливо:** у репозиторій завантажується **вміст** теки `lps`, а не
   сама тека. Тобто в корені репозиторію мають опинитися `app`, `site`,
   `.github`, `tlumach_kotoba.py` тощо. Якщо завантажити теку `lps`
   цілком, GitHub не побачить `.github/workflows` і збірка не запуститься.
3. Увімкніть показ прихованих файлів, щоб бачити теку `.github`:
   Провідник → вкладка **Перегляд** (Windows 11: **Показати**) →
   **Приховані елементи**.

## Крок 2. Впишіть своє ім'я GitHub у сайт

Посилання на завантаження в сайті містять заглушку `YOUR_GITHUB_NAME`.
Її треба замінити на ваше ім'я користувача GitHub **до** завантаження
файлів (або потім — через редагування на GitHub, див. Крок 9).

1. Відкрийте `site\index.html` у Блокноті (правою кнопкою → Відкрити за
   допомогою → Блокнот).
2. Натисніть **Ctrl+H** (Замінити).
3. «Що»: `YOUR_GITHUB_NAME`, «Чим»: ваше ім'я на GitHub (наприклад
   `ted-ukr`). Натисніть **Замінити все** → збережіть (**Ctrl+S**).
4. Те саме зробіть у `site\methodology.html` і `site\404.html`.

Якщо назвете репозиторій **не** `tlumach-kotoba`, так само замініть і
`tlumach-kotoba` у посиланнях (шукайте `github.com/` у файлах).

## Крок 3. Створіть репозиторій на GitHub

1. Увійдіть на github.com → праворуч угорі **+** → **New repository**.
2. **Repository name:** `tlumach-kotoba`.
3. **Public** — обов'язково, якщо хочете, щоб інші люди могли
   завантажувати програму з сайту (з приватного репозиторію релізи
   стороннім недоступні).
4. **Не** ставте галочки «Add a README», «.gitignore», «license» — усе
   потрібне вже є в архіві.
5. **Create repository**.

## Крок 4. Завантажте файли

### Варіант A — через браузер (найпростіше для першого разу)

1. На сторінці нового порожнього репозиторію натисніть посилання
   **uploading an existing file**.
2. Виділіть у Провіднику **весь вміст** теки `lps` (Ctrl+A — разом із
   `.github` та `.gitignore`) і перетягніть у вікно браузера (Chrome або
   Edge підтримують перетягування тек).
3. Дочекайтеся, поки всі файли підвантажаться, внизу напишіть коментар,
   наприклад `Перша версія`, і натисніть **Commit changes**.
4. **Перевірте**, що в репозиторії є тека `.github` → `workflows` →
   `build-windows.yml`. Браузер іноді пропускає приховані теки.
   Якщо її немає:
   - **Add file** → **Create new file**;
   - у полі назви наберіть `.github/workflows/build-windows.yml`
     (з косими рисками — GitHub сам створить теки);
   - вставте вміст файлу `build-windows.yml` з архіву (відкрийте його
     Блокнотом, Ctrl+A, Ctrl+C) → **Commit changes**.

### Варіант B — GitHub Desktop (зручніше для подальших оновлень)

1. Встановіть [GitHub Desktop](https://desktop.github.com) і увійдіть
   своїм акаунтом.
2. **File** → **Clone repository** → виберіть `tlumach-kotoba` → оберіть
   теку на диску → **Clone**.
3. Скопіюйте весь вміст теки `lps` у цю теку клону.
4. У GitHub Desktop з'явиться список змін. Внизу ліворуч напишіть
   `Перша версія` → **Commit to main** → угорі **Push origin**.

## Крок 5. Перша збірка програми

Одразу після завантаження файлів GitHub почне збирати `.exe`.

1. У репозиторії відкрийте вкладку **Actions**.
2. Якщо бачите повідомлення «Workflows aren't being run on this forked
   repository» або кнопку **I understand my workflows, go ahead and enable
   them** — натисніть її.
3. Ліворуч виберіть **Build Windows EXE**. Якщо запуску ще немає —
   праворуч **Run workflow** → гілка `main` → **Run workflow**.
4. Зачекайте 5–10 хвилин. Жовтий кружечок — триває, **зелена галочка** —
   готово, **червоний хрестик** — помилка.
5. Відкрийте успішний запуск → внизу розділ **Artifacts** →
   **TlumachKotoba-windows-exe**. Завантажиться zip, усередині —
   `TlumachKotoba.exe`. Перевірте, що він запускається.

Якщо з'явився червоний хрестик: відкрийте запуск → клікніть крок із
хрестиком → скопіюйте останні рядки журналу і надішліть їх — розберемо.

## Крок 6. Перший реліз (саме з нього качає сайт)

Файл з **Artifacts** бачите лише ви. Щоб програму могли завантажити
всі — опублікуйте реліз:

1. На головній сторінці репозиторію праворуч **Releases** →
   **Create a new release** (або **Draft a new release**).
2. **Choose a tag** → введіть `v1.0.0` → **Create new tag: v1.0.0 on
   publish**.
3. **Release title:** `Tlumach Kotoba 1.0.0`. В описі коротко —
   що вміє версія (можна лишити порожнім).
4. **Publish release**. Сам `.exe` вручну **не** додавайте.
5. Відкрийте вкладку **Actions** — там запуститься нова збірка (тригер
   «release»). Через 5–10 хвилин поверніться до релізу: у розділі
   **Assets** з'явиться `TlumachKotoba.exe`.

Тепер пряме посилання працює:
`https://github.com/ВАШЕ_ІМ'Я/tlumach-kotoba/releases/latest/download/TlumachKotoba.exe`
— відкрийте його в браузері, завантаження має початися одразу.

## Крок 7. Сайт на Cloudflare Pages

1. Зареєструйтеся на [dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up)
   (безкоштовний план). Власний домен **не** потрібен — сайт отримає
   адресу виду `tlumach-kotoba.pages.dev`.
2. У меню ліворуч відкрийте **Workers & Pages** (може бути в розділі
   **Compute**) → **Create**.
3. Оберіть вкладку **Pages** → **Import an existing Git repository**
   (кнопка може називатися **Connect to Git**).
   Якщо Cloudflare пропонує створити **Worker** з полем «Deploy
   command» — це інший сценарій; поверніться і виберіть саме **Pages**.
4. **Connect GitHub** → GitHub попросить дозвіл для Cloudflare →
   оберіть **Only select repositories** → `tlumach-kotoba` → **Install &
   Authorize**.
5. Виберіть репозиторій `tlumach-kotoba` → **Begin setup**.
6. Заповніть налаштування **точно так**:

   | Поле | Значення |
   |---|---|
   | Project name | `tlumach-kotoba` |
   | Production branch | `main` |
   | Framework preset | `None` |
   | Build command | *(порожньо)* |
   | Build output directory | `site` |

   **Build output directory = `site`** — найважливіше поле. Саме тому
   Cloudflare покаже сайт, а не файли програми.
7. **Save and Deploy**. Приблизно за хвилину з'явиться посилання
   `https://tlumach-kotoba.pages.dev` (якщо назва зайнята — Cloudflare
   додасть суфікс, адресу побачите на екрані).
8. Відкрийте сайт і натисніть **Завантажити для Windows** — має
   завантажитися `.exe` з Кроку 6.

**Запасний варіант без GitHub:** Workers & Pages → Create → Pages →
**Upload assets** → перетягніть теку `site`. Сайт запрацює, але
оновлюватиметься лише вручну.

## Крок 8. Власний домен (необов'язково)

Pages → ваш проєкт → **Custom domains** → **Set up a custom domain** →
введіть домен і дотримуйтеся підказок Cloudflare (для домену, що вже в
Cloudflare, записи створяться автоматично).

## Крок 9. Як оновлювати надалі

| Що змінилося | Що зробити | Що станеться |
|---|---|---|
| Код програми | Commit + push у `main` | Actions збере новий `.exe` (Artifacts) |
| Нова версія для людей | Новий реліз: тег `v1.0.1`, `v1.1.0`… | `.exe` прикріпиться до релізу, кнопка сайту почне качати нову версію |
| Сайт (`site/`) | Commit + push у `main` | Cloudflare оновить сайт приблизно за хвилину; збірка `.exe` при цьому **не** запускається |

Змінити файл просто на GitHub: відкрийте файл → значок олівця
(**Edit this file**) → правки → **Commit changes**.

## Крок 10. Перевірка

- [ ] У репозиторії є `.github/workflows/build-windows.yml`
- [ ] Остання збірка в Actions — із зеленою галочкою
- [ ] У релізі `v1.0.0` в **Assets** є `TlumachKotoba.exe`
- [ ] Посилання `…/releases/latest/download/TlumachKotoba.exe` качає файл
- [ ] Сайт на `*.pages.dev` відкривається, кнопка «Завантажити» працює
- [ ] Сторінка «Методологія» відкривається з сайту

## Типові проблеми

**У вкладці Actions порожньо / немає «Build Windows EXE».**
Тека `.github` не потрапила в репозиторій або лежить не в корені (напр.
`lps/.github`). Див. Крок 4, пункт 4.

**Збірка не стартувала після релізу.**
Переконайтеся, що реліз саме **опублікований** (не чернетка). Можна
запустити вручну: Actions → Build Windows EXE → Run workflow — але тоді
`.exe` потрапить лише в Artifacts, не в реліз.

**Помилка на кроці «Attach EXE to the GitHub Release» (403 / permission).**
Settings → Actions → General → **Workflow permissions** → **Read and write
permissions** → Save. Потім Actions → невдалий запуск → **Re-run jobs**.

**Кнопка «Завантажити» на сайті дає 404.**
Або ще немає опублікованого релізу з `.exe` (Крок 6), або в посиланні
лишилося `YOUR_GITHUB_NAME`, або репозиторій названо інакше (Крок 2).

**Cloudflare показує 404 замість сайту.**
У налаштуваннях проєкту Pages → **Settings** → **Build** →
**Build output directory** має бути `site`. Після зміни — **Deployments**
→ **Retry deployment**.

**Windows пише «Windows захистив ваш ПК».**
Програма не має платного цифрового підпису — для нових невідомих файлів
це звичайне попередження SmartScreen. **Докладніше** → **Виконати в
будь-якому разі**. Про це ж сказано на сайті в розділі «Встановлення».

**Програма запускається, але MP3 не створюється.**
FFmpeg вбудований у `.exe`, тож найчастіша причина — немає інтернету
(він потрібен для озвучення реплік). Перевірте з'єднання й повторіть.

---

*Примітка:* workflow і сайт перевірені лише локально (синтаксис YAML,
коректність HTML). На справжньому GitHub і Cloudflare вони вперше
запрацюють у вас — якщо якийсь крок поведеться інакше, ніж описано,
надішліть скріншот або текст помилки.
